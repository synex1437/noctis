# Noctis — reference

The README says what the plugin does and how to install it; this page lists every command, configuration key, host adapter and file.

## Commands

Two flags work with every command: `--account <dir>` is the account folder whose `noctis/` data is used (default `CLAUDE_CONFIG_DIR`, else `~/.claude`; when `--host` or `NOCTIS_HOST` names another tool, that tool's home), and `--host <id>` picks the host adapter (`claude`, `codex`, `antigravity`, `droid`, `copilot`). `setup` and `install` configure every account named with `--config-dir` or `--account` (both can be repeated, a leading `~` is expanded, duplicates are dropped). Flags are written `--flag value` or `--flag=value`; `-h` prints the help, as `--help` does, and `-v` prints the version, as `--version` does. An unknown `--host` or `NOCTIS_HOST` makes any command you run exit 2 with the list of valid ids, and a valid `--host` wins over a bad `NOCTIS_HOST`; the commands a host or noctis itself starts (`hook`, `statusline`, `resume`, `sleeper`, `ensure`, `release-check`, `webhook`, `selftest-mark`, `state-write`) ignore the bad value and use the configured host, Claude Code by default.

An unknown option (with a did-you-mean), a stray word, a flag missing its value, a switch given one, or a `--permissions` or `--updates` value outside its list exits 2 with nothing written; an unknown preset, profile or role value exits 1, also before anything is written. A role's model must be one Claude Code knows: an alias (`opus`, `sonnet`, `haiku`, `fable`, `best`, `opusplan`, `default`, `inherit`, also with `[1m]`), a name with a model family in it, or a full `claude-…` id. That rule is for Anthropic's own API: when the account's Claude Code uses another provider or a gateway — one of the `CLAUDE_CODE_USE_BEDROCK`, `_VERTEX`, `_FOUNDRY`, `_ANTHROPIC_AWS`, `_ANTHROPIC_GOOGLE_CLOUD`, `_MANTLE` or `_GATEWAY` switches set to `1`, `true`, `yes` or `on`, or an `ANTHROPIC_BASE_URL` on a host outside anthropic.com, in the environment or in the `env` of its `settings.json` — the provider decides which ids exist, so any id made only of letters, digits and `. _ : @ / [ ] -` is taken, such as a deployment or gateway name, or an inference-profile ARN in the `roles` section of `config.json`; `noctis doctor` and the agent files follow the same rule. A `config.json` that exists but cannot be read stops setup with exit 1 and nothing changed; one that cannot be written stops it before `settings.json` is touched. With another `--host`, it installs for that tool instead, as `install` does |
| `install` | the setup flags (`--updates` is accepted and changes nothing here), plus `--source <dir>` and `--uninstall` | Copies the plugin from `--source` (default: the running plugin) into `<account>/skills/noctis/` — `<tool home>/noctis/plugin/` for another tool — with the hooks module `hooks/hooks.json` names under `modules` (a name that leads outside the plugin is not copied), and checks and places the binary. For Claude Code it then points the copy's hooks at the binary and configures the account as `setup` does; for another tool it writes that tool's hook file. A `config.json` that exists but cannot be read stops it with exit 1 before anything is copied, and the argument checks and exit codes of `setup` apply. `--uninstall` first puts back the `settings.json` values setup recorded (a value it holds no record of stays as it is) and forgets those records, so a later setup starts over as a first one, then removes the copy (for another tool: removes its hook entries); it exits 1 and leaves the plugin in place when `settings.json` or `config.json` cannot be read or `settings.json` cannot be written — for another tool, when its hook file or Antigravity's `settings.json` cannot be read. In a terminal without `--host`, it asks which tool |
| `ensure` | — | Run by the SessionStart hook at startup: places the binary (unless `bin/noctis` is already a hard link of the platform binary); on the first run writes `config.json`; points the status line at the plugin whenever another one has taken its place, keeping that one as `statusline.chainCommand` (setup does the same), so a status line you switch to after installing is shown above noctis's and put back by uninstall; adds the config sections a new version brings; keeps the agent files in step with the roles; repairs the status-line path. While `config.json` cannot be read it changes neither that file nor a status line another tool set, and leaves the agent files alone |
| `webhook` | `--title`, `--body` | Posts one message to the configured webhook now, even with `alarm.enabled: false`, and says whether it was delivered: exit 0 when it was; exit 1, with the reason on stderr, when no `alarm.webhook.url` is set, the address is not usable, the circuit breaker is open or the delivery failed. Without `--title` and `--body` it sends a test message and ignores an open circuit |
| `version`, `help` | — | The version (`--version` and `-v` too); the commands in this table with one line each (`--help` and `-h` too). An unknown command exits 1 and lists them |

Called by the plugin itself: `hook`, `statusline`, `resume`, `sleeper`, `release-check`, `selftest-mark`. `state-write` is for the test harness.

A command you run that crashes prints `noctis <command> crashed: <reason>` with the path of `errors.log` on stderr and exits 1. The commands a host or noctis itself starts exit 0 after a crash, so a hook never fails the session; a crashed status line prints `∞ noctis error (errors.log)`. `webhook` is the exception: you run it yourself to test the webhook, so a crash in it exits 1 with that message too.

`noctis check` is the exit-code gate for crons, CI and other agents: `0` under every threshold, `10` inside the warn band, `11` a threshold is reached (the hooks would pause right now), `20` no or stale usage data, `2` an unknown `--host` or `NOCTIS_HOST`, `1` a crash of noctis itself (the reason is in `errors.log`). `11` also covers a window at the 100 % ceiling or about to cross it and a Fable session over the Fable threshold; a `budget.hardStop` pause is not reflected. It records nothing and never touches the network.

`report --json` is ccusage-compatible (`daily[]` with `inputTokens/outputTokens/cacheCreationTokens/cacheReadTokens/totalTokens/totalCost/modelsUsed/modelBreakdowns`) and adds `keptOffPrimary` — the tokens subagents spent on other models instead of the primary one, with the API-equivalent cost they avoided. Costs use the published list prices (informational on a subscription); `report.pricing` in `config.json` overrides or extends the table.

## Slash commands and agents

| Inside Claude Code | What it runs |
|---|---|
| `/noctis:setup` | Asks which roles profile you want (unless you pass `--profile` or a role flag), then runs `noctis setup --profile …` with your words written as flags (`economy` becomes `--profile economy`, a folder `--config-dir <folder>`) |
| `/noctis:status` | `noctis status`, then `noctis why --last 10` |
| `/noctis:pause [minutes]` | `noctis off <minutes>`; the skill turns a duration such as `2 hours` into minutes (default 60, at most one week) |
| `/noctis:resume` | `noctis on` |

While one of these runs, Claude may use the plugin's own binary for that command without asking (for `/noctis:status`, `status` and `why`), and nothing else: any other command it runs meanwhile goes through your permission settings as usual. `/noctis:setup` and `/noctis:pause` start only when you type them; Claude cannot start them itself, even when a file it reads asks it to.

These four prompts pass the pause point, though not the 100 % ceiling (nor a window about to cross it), so you can check, pause or set up the plugin at a limit; a tool batch that only runs the plugin's own binary (plain Bash or PowerShell calls with plain arguments, no pipes, redirections or other commands) is not held either. `noctis why` shows them as `control-prompt`, `control-batch` and, at the ceiling, `block-control-prompt`. Your answer to a question the skill asks is an ordinary prompt and meets the pause point like any other.

Two agents come with the plugin. `noctis:lite` does research and writing on the `roles.research` model; it may write only `.adoc .csv .markdown .md .rst .srt .tsv .txt .vtt` files — the PreToolUse hook denies a `Write` to any other file, and its frontmatter keeps `Edit`, `MultiEdit` and `NotebookEdit` away from it. `noctis:digest` runs noisy commands (test suites, builds, long logs) on the `roles.digest` model and returns a digest; it never writes files (its frontmatter disallows the file tools, and the hook denies a `Write`). These write limits apply in observe mode too and are not journaled. A hand-made agent named in `router.agent` or `router.digestAgent` has to keep `Edit`, `MultiEdit` and `NotebookEdit` out of its tools the same way, because the hook never sees those calls; `noctis doctor` and the startup self-check name an agent file that allows one. Unless the router is off, the guard is paused or observe mode is on, a prompt that starts with `lite:` is always sent to `noctis:lite`; one that starts with `main:` or `fable:` never is. A session started with `claude --agent <name>` (or the `agent` setting) is guarded like any other main session; one that runs as the lite agent itself is not told to hand its research to that agent.

**Subagents at a limit (Claude Code).** Subagents and workflow agents meet the pause point and the credit ceiling on their own loop. Past the pause point, a subagent's `WebSearch`, `WebFetch`, `Agent`, `Task`, `Workflow` or `Write` call is denied with an instruction to start no new work and report what it has; its first tool batch past that point carries the same instruction, and the next one ends the agent. At the ceiling it is ended at once. Batches that only deliver the report (`SubagentHandback`, `StructuredOutput`) pass, and a subagent's `Workflow` also meets the warn band and the fan-out headroom. Each agent cut short is named — `<type> agent <id> — stopped by the usage limit at <time>; its result is partial`, or `told at <time> to wrap up …; its result may be partial` — in the checkpoint, in the note a relaunch or wake starts with, and in the context after an in-hook wait, so the resumed session redoes that part instead of trusting a saved result. The journal actions are `deny-subagent-tool`, `warn-subagent` and `stop-subagent`. On the other tools, subagents are not guarded this way.

Claude Code hook events wired in `hooks/hooks.json`: `SessionStart` (on `startup` it also runs `noctis ensure`), `SessionEnd`, `UserPromptSubmit`, `PreToolUse` (`WebSearch|WebFetch|Agent|Task|Workflow|Write`), `PostToolBatch`, `StopFailure` (`rate_limit|overloaded|server_error|model_not_found|billing_error|account_on_hold|authentication_failed`), `Notification` (`quota_auto_resume_fired|quota_auto_resume_stale|quota_auto_resume_disabled`), `PostModelSwitch`, `TaskCreated`, `TaskCompleted`, `PostToolUse` (`Agent|Task`), `Stop`, `PermissionRequest` (`Read|Edit|MultiEdit|Write`; see `queue.auto`). In a run Claude Code treats as non-interactive (`CLAUDE_CODE_ENTRYPOINT` `sdk-cli`, which is `claude -p`, `sdk-ts`, `sdk-py` or `claude-code-github-action`), Claude Code starts the asynchronous `StopFailure` hook while it is already shutting down and does not always wait for it, so there the hook ignores SIGTERM, writes the payload to `<account>/noctis/pending/` and exits after starting a detached `noctis hook --input <file> --account <account>`; that copy stores the checkpoint, the retry and its scheduled relaunch, removes the file and never wakes the session in place. Interactive sessions keep the in-hook path and the same-session wake, and when the copy cannot be started the hook does the work itself. A `SessionEnd` that runs while such a hand-off (younger than an hour) is pending keeps the session's workflow record for the relaunch. On `startup` and `/clear`, `SessionStart` hands the new session the latest unused checkpoint of its folder (at most 7 days old), except one whose own session will still be resumed — its wait is pending or its relaunch is running. A checkpoint counts as used once its own session goes on: a prompt there passes the guard, or the guard is paused. Under `modules` it also names the hooks module `hooks/lean.js`, which Claude Code loads only with function hooks on (`CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1`); it hooks `session.start`, `session.compact` and `turn.complete`. A value of the wrong type or out of range in the `compaction` keys it reads is replaced by the shipped one. While `compaction.lean` is on and prompt caching is off (`DISABLE_PROMPT_CACHING`, the only time it trims), it declines a summary Claude Code computes ahead of time (`precompute`): once the rows are trimmed, Claude Code would discard that summary. A message it trims goes to the summary without Claude Code's handle, so Claude Code rebuilds it from its role, text and tool blocks alone (Claude Code's contract for a rewritten message); a message it leaves alone keeps its handle and stays whole.

## Configuration — `<account>/noctis/config.json`

| Key | Default | Meaning |
|---|---|---|
| `locale` | `auto` | `auto` follows the language of each session's prompts (en, tr, de, fr, es, pt, it, nl, pl, ru, ja, zh, ko, ar), before that `LC_ALL`/`LC_MESSAGES`/`LANG`; or pin one code. The `NOCTIS_LANG` environment variable overrides both |
| `roles.profile / code / research / planning / digest / explore / fallback` | noctis / opus:max / opus:xhigh / opus / haiku / haiku / opus:max | Which model (and effort) does which work; setup writes it and projects it onto `models.*`, `router.subagentModels` and the plugin's own agents; `noctis ensure` keeps the agents in step after marketplace updates, as long as `config.json` can be read |
| `workflow.suggest / gate / size` | true / true / medium | Suggest a dynamic workflow (ultracode) for fan-out prompts and queue items, with per-role models — only when the gate would let the launch through, and naming `models.fallback` for a role on the scoped model while its quota is out; deny a new `Workflow` launch inside the warn band, over a threshold, or without `credits.fanOutHeadroom` points of room in every window it can draw on. The Fable bucket counts only when Fable could run the agents: the session model matches `models.scopedPattern`, a role the advice names does (after the swap to `models.fallback` while the quota is out), or, for a launch, the script (`script`, or the file at `scriptPath`, relative paths from the session's folder) or its `args` match it, the script starts another workflow, it gives an agent an `agentType` other than a quoted `noctis:<name>` (the model of any other type is not known) or a `noctis:<name>` whose `agents/<name>.md` cannot be read or names a matching model (setup writes the research and digest roles' models there), or there is no script to read (a launch by `name` or run id alone, a file that cannot be read or is over 1 MiB); a subagent's launch always counts it, since the subagent's own model is not known; the size hint passed along |
| `mode` | `enforce` | `observe` = journal the limit, queue and routing decisions as `would-…` and enforce none of them, including the 100 % ceiling (paid overflow is possible), and start no checklists from prompts. Three things still happen: the lite/digest write limits apply (not journaled), a `model_not_found` error still rewrites `model` in `settings.json`, and `queue.github.closeOnDone` still closes issues |
| `thresholds.session5h / weeklyAll / weeklyFable` | 92 / 89 / 95 | Pause points in % (above 0, at most 100; `weeklyScoped` is an alias for the scoped model). `0`, `null` or `false` switches a threshold off — status, doctor and the self-check still point it out, and the 5-hour or weekly window then stops only at `credits.ceiling` (a switched-off `weeklyFable` leaves the Fable bucket unwatched); any other out-of-range value falls back to the shipped default and is named in status, doctor and the session self-check. | `credits.allowPaid / ceiling / fanOutHeadroom` | false / 100 / 25 | Work stops when a 5-hour or weekly window reaches `ceiling` %, or when the burst and stale-data projection a threshold uses say it is about to (hit label `usage limit about to be reached`), whatever the thresholds say and even while `noctis off` is active, because past 100 % the account pays for the overflow. Within 8 points of `ceiling` the usage endpoint is polled as within 8 points of a pause point, also while `noctis off` is active; with the guard on, a window there whose data stops arriving is probed and paused as near a pause point (`usage.blindProbeRounds`); `allowPaid: true` lifts this (doctor and the self-check flag it, except on Droid and Copilot, which have no limit guard). A new Workflow is denied unless every window it can draw on has `fanOutHeadroom` points left before its pause point (the Fable bucket when it is reported and Fable could run the workflow's agents, see `workflow.gate`); `0` turns that check off. A `ceiling` outside 1–100 falls back to 100 |
| `models.primary / fallback / effort` | opus / opus / max | Default model; the model to switch to when the scoped quota is out (with `roles.fallback.effort`, switched back after the reset; a setup run during the switch keeps a Fable or Opus fallback model, as it keeps any Fable or Opus model it did not write, and sets only the effort, so unless `models.primary` names that model the reset puts in the model the setup would have chosen without the switch: `models.primary`, or a Fable or Opus model picked by hand before the switch); effort level |
| `models.scopedPattern / scopedLabel` | `fable` / Fable | Which OAuth bucket and which model names the scoped rule applies to; setup keeps it on Fable (the one per-model weekly cap noctis watches) unless the code model is Fable or Mythos itself |
| `router.enabled / agent / minPromptLength / maxDeniesPerPrompt` | true / lite / 15 / 3 | Research router: research and writing prompts go to `noctis:<agent>`; prompts shorter than `minPromptLength` characters are left alone; on a routed prompt the main session's WebSearch/WebFetch is denied at most `maxDeniesPerPrompt` times. A link to a pull request, issue, commit, compare view, file or CI run on GitHub, GitLab or Bitbucket, or to a local server (`localhost`, `127.x`, `0.0.0.0`, `[::1]` or any host with a port), counts as code and keeps the prompt on the main model; `lite:` still forces it to the agent. Asking to review or benchmark something is not a research signal, nor is a single *source*, *trend*, *article* or *price*: the nouns *reviews*, *benchmarks*, *sources*, *trends*, *articles* and *prices* are, and *price of*; in Turkish *güncel*, *kaynak*, *kaynaklar*, *incelemeler* and *trendler* are, while *güncelle* and *kaynaklanıyor* are not. A singular *incelemesi* is, like *araştır* or *investigate*, an ask to investigate, which on its own routes a prompt only in a session with no file edit and no command in its last 45 minutes; *kod incelemesi* stays on the main model in any session, for its code word *kod* |
| `router.digest / digestAgent` | true / digest | `digest: true` adds the `noctis:<digestAgent>` subagent to the queue instructions, for long test runs, big diffs and noisy logs |
| `router.subagentModels` | `{"Explore": "haiku", "Plan": "opus"}` | Model pinned to built-in subagents spawned without one (setup projects the roles profile onto it). While the scoped (Fable) quota is out — the bucket at or over its threshold, or the model switch still standing for that window — a pin to the scoped model and an explicit scoped `model` on an Agent/Task call both run on `models.fallback`; `noctis why` shows it as `subagent-fallback` |
| `fable.source / pollMinutes / revertOnReset / autoRelaunch` | oauth / 10 / true / true | Where usage beyond the status line comes from (`oauth`: the OAuth usage endpoint; `codex`: `codex app-server`, set by a Codex install; `off`: nowhere, set for the other tools), the minimum minutes between routine fetches, switching back after the reset (to the model and effort `settings.json` had before the switch, removed again when it had none; a model or effort changed since, or set by a setup run since, is left as it is), relaunching a session on the fallback role's model and effort (so is a session that waited for another limit when the scoped cap is still out, and the same-session wake leaves such a session to that relaunch). **Parallel pauses.** Hooks of one session that pause for the same limit at the same moment — several Agent calls fanned out at once, or the per-call `PostToolUse` hooks of Codex and Droid — share one wait: a pause joins the stored wait when it is for the same window, its reset is within 2 s, it was stored less than 120 s ago and the pause is not a prompt. Every hook then holds until the reset, or until an early reset or fresh data releases the wait. A hook clears only the wait it stored itself; if another pause for the same reset replaced it, it holds on that one, and if a different pause replaced it (another window, or a wait handed to the runner), it stops with that pause's `work saved, auto-resume at …` message, followed by that pause's reason when it did not come from its pause point. `noctis why` logs these as `join-wait` and `wait-replaced`.

## Other AI coding tools

The engine is host-independent; a thin adapter per tool writes that tool's hook file, translates hook JSON in and out, reads usage where the tool exposes it, and resumes sessions with the tool's own command. `scripts/install.sh` / `install.ps1` (or `noctis setup` in a terminal) ask **which tool** with a numbered list; `--host <id>` skips the question. The answer can be the number, the id, the tool's full name, or three or more letters that start a word of exactly one tool's name (`ant`, `cop`); an empty answer means Claude Code, and anything else is asked again. On Windows the question appears in a console (PowerShell, cmd, Windows Terminal) but not in Git Bash or mintty, whose stdin is a pipe: pass `-Tool` / `--host` there. `install.ps1 -Tool` takes an id; a display name such as `'Codex CLI'` exits 2 with the list of ids.

Claude Code's relaunch runs in the folder the session started in (its `CLAUDE_PROJECT_DIR` at the pause), not in a subfolder Claude had moved into with `cd`: Claude Code gives a resumed session's hooks the folder it is started in as `CLAUDE_PROJECT_DIR`, so this keeps the session's queue in reach. A session started with `claude -w` has its worktree as that folder, and one that entered a worktree with `EnterWorktree` is put back into it by Claude Code. The queue the relaunch prompt names is looked up as the hooks look it up, in the folder the session started in and then in the one it paused in; when it is found only in the one it paused in (a subfolder's own queue), the relaunch runs there instead, where its hooks find it again. The relaunch also passes `--model`, `--effort` and `--permission-mode` (and `--remote-control` with `resume.remoteControl`); `resume.extraArgs` are added for every tool, except flags that would lift the permissions the resume settings chose: `--dangerously-skip-permissions`, `--allow-dangerously-skip-permissions` and `--permission-mode` for Claude Code, `--dangerously-bypass-approvals-and-sandbox` for Codex, `--allow-all-tools` for Copilot (`resume.copilotAllowAllTools` decides that) and `--auto` and `--skip-permissions-unsafe` for Droid (`resume.droidAuto` sets the level); those are dropped with a warning and journaled as `extra-arg-dropped`. Claude Code and Codex get the prompt after `--`, so a prompt is never read as an option, and for every tool a prompt that would start with `-` starts with `Continue. ` instead. Every relaunch starts the tool without the session markers Claude Code gives its hooks (`CLAUDECODE`, `CLAUDE_CODE_SESSION_ID`, `CLAUDE_CODE_CHILD_SESSION`, `CLAUDE_CODE_SESSION_ATTENDED`, `CLAUDE_PID`, `AI_AGENT`, `CLAUDE_EFFORT`, `TRACEPARENT`, `CLAUDE_CODE_ENTRYPOINT`), so the relaunched session carries no marker of the session that paused and starts as a session of its own.

Not supported (checked September 2026): Gemini CLI (consumer access ended June 2026 — use Antigravity CLI), Kiro CLI (`AgentStop` cannot block), Cursor / OpenCode / Amp / Qwen Code (hooks exist but no script-readable limits; queue-only support is on the list), Roo Code (archived), Cline / Goose / Crush (no continue hook).

Install for another tool from the zip or clone: `./scripts/install.sh --host codex` (macOS/Linux) or `.\scripts\install.ps1 -Tool codex` (Windows); the plugin lands in `<tool home>/noctis/plugin/` with its config next to it, and `noctis doctor --host codex` checks the wiring. Uninstall: the same command with `--uninstall` / `-Uninstall` — it removes only the plugin's own hook entries (on Antigravity also the `statusLine` it wrote) and the `<tool home>/noctis/plugin/` copy; the config and logs next to it stay.

**Honest status:** the four adapters implement each tool's documented hook, usage and resume contracts and pass the black-box lab against stand-ins of those tools. A weekly CI job (`real-tools.yml`) installs the real Claude Code, Codex and Copilot CLIs and checks that the main flags the plugin passes are still there, and that `codex app-server` answers the handshake; it never signs in or runs a model, and Antigravity and Droid are not checked. No adapter has run a real session end to end yet — smoke tests are in [docs/HOSTS.md](HOSTS.md); reports with the tool's version are welcome.

## Files (`<account>/noctis/`)

| File | What it holds |
|---|---|
| `config.json` | Your configuration (the table above) |
| `usage.json` (+ `.bak`) | Status-line captures, per-session model, context and the version its status line reported, burst history — a stable contract other status lines can read; each window also carries `at`, the time it was last reported |
| `fable.json` | The windows from the last OAuth usage fetch (on Codex, from `codex app-server`), with its error and back-off |
| `release.json` | The last published version the daily check saw |
| `state.json` (+ `.bak`) | Pending waits and hand-offs, checkpoint records, queue trust, what the router learned, notices already shown |
| `decisions.jsonl`, `guard.log`, `errors.log` | The journal behind `noctis why`, the full log, and its WARN/ERROR lines — each rotated to `.1` at 512 KB |
| `resume-output.log` | Output of headless relaunches, rotated at 512 KB |
| `hooks-debug.log` | Raw hook payloads, only with `NOCTIS_DEBUG_HOOKS` |
| `checkpoints/<sid>.md` | The checkpoint of each paused session, kept 7 days |
| `queues/<session>.md` | Checklists noctis wrote from long prompts; one is removed when its job is done or you steer the session by hand, otherwise 7 days after it last changed, and never while its session waits on a pause |
| `quiet/<session>.json` | Markers for the quiet fast path |
| `compact.log` | One JSON line per compaction the lean module trimmed: `at`, `sid`, `trigger` (`auto`, `manual`, `plugin`), `rows`, `changed`, `trimmed` (characters), the `tokensBefore` and `tokensAfter` Claude Code reported, `agent` for a subagent's own compaction and, for an early one, `ctx`, the context fill that asked for it; the last 200 are kept. `noctis status` counts them, `noctis why` lists them |
| `lean.json` | The sessions the lean module ran in, the last 50; a session missing from it gets the `ctx ▲` mark and the `/compact` notice |
| `launches/` | Relaunch scripts, pid files, selftest markers |
| `pending/` | The `StopFailure` payload of a `claude -p` or Agent SDK run while the detached copy it was handed to stores the retry; removed when the copy finishes. One the copy never removed is swept once it is an hour old, a half-written one after five minutes |
| `runner.cmd` | Windows: the launcher the scheduled task runs; it switches its console to UTF-8 (code page 65001) first, so a profile path with letters such as Ç, ü or Cyrillic still resolves |
| `*.lock` | `state`, `usage`, `fable`, `settings`, `schedule-<hash>`. On macOS and Linux the process that holds one also keeps an `flock` on it; a lock left by a process that died is removed only when nobody holds that flock and only if it is still the file that was judged stale, and a process lets go of a lock only while the file is still its own. The exception: a lock more than two minutes old whose recorded pid is a running process counts as hung and is taken over without the `flock` test — also when that process is a new one that got the dead holder's pid |
| `noctis-bundle-<time>.zip` | `noctis report --bundle` without a file name |

Outside that folder: `<account>/settings.json.bak-<time>` (setup and install back up `settings.json` before they change it), `<account>/skills/noctis/` (a clone install), and, only while a resume is pending, the Task Scheduler task `Noctis-<hash>`, `~/Library/LaunchAgents/com.synex.noctis.<hash>.<epoch>.plist` (one per scheduled resume) or the systemd user unit `noctis-<hash>-<epoch>` (one per scheduled resume).

## Limits

Usage data comes from Claude Code's official `statusLine` payload (`rate_limits`, Claude Code ≥ 2.1.251) and from the undocumented OAuth usage endpoint, which supplies the scoped bucket and backs up the 5-hour and weekly windows when status-line data is stale — keep an eye on `errors.log` after Claude Code updates; `selftest` reports the tested version range. Same-session wake relies on `asyncRewake`, which is documented as observational; the scheduled relaunch covers the case where it stops working. Lean compaction runs on Claude Code's early-access function hooks (tested with 2.1.281), which may change between releases; without them, compaction is Claude Code's alone.
