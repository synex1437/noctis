---
name: setup
description: One-time setup of noctis after installing it from a marketplace — asks which model and effort should do which kind of work, places the native engine binary, wires settings.json (statusLine, model, effort, the function hooks switch lean compaction needs, and where Claude Code compacts) and runs the doctor. Use when the user asks to set up, install, configure or repair noctis, or to change which models it uses.
allowed-tools:
  - Bash("${CLAUDE_PLUGIN_ROOT}/bin/noctis" setup *)
disable-model-invocation: true
---

Speak the user's language throughout (the language they are writing in right now).

**Step 1 — ask which model does which work** (skip this step if `$ARGUMENTS` already contains `--profile` or a role flag). Ask one question with these choices and wait for the answer:

1. **Code** (the default) — for people who mostly write code: code and planning on **Opus 5.5 · xhigh**, research and writing on Sonnet 5.5 · high, noisy-output digests and file search on Haiku 5.5, which needs Claude Code 2.1.293 or newer (an older one, or Bedrock, Vertex AI or Foundry, runs Haiku 4.5).
2. **Search** — for people who mostly research and write: research and writing on **Opus 5.5 · xhigh**, code and planning on Opus 5.5 · xhigh, digests and search on Haiku 5.5.
3. **Balanced** — spends less of the usage limits: code, research and writing on **Sonnet 5.5 · high** (half Opus's price per token), planning on Opus 5.5, digests and search on Haiku 5.5. Sonnet 5.5 needs Claude Code 2.1.284 or newer.
4. **SYNEX** (the only profile at max): code and planning on **Opus 5.5 · max**, research and writing on **Opus 5.5 · xhigh**, digests and search on Haiku 5.5. Opus 5.5 beats Fable 5.1 on every coding benchmark Anthropic published with it, and every paid plan includes it. No setting saves max, so setup puts it in `env.CLAUDE_CODE_EFFORT_LEVEL`, which overrides every other level: a typed `/effort` and the effort of noctis's own subagents too.
5. **custom**: ask for each role separately — code, research & writing, planning, noisy-output digests, file search, fallback — as `model` or `model:effort` (models: fable, opus, sonnet, haiku or a full model id; effort: low, medium, high, xhigh, max). Planning and file search take a model only, since the Agent tool has no effort to give them, and Haiku 4.5 takes no effort at all.

Then ask one more question and wait for the answer (skip it if `$ARGUMENTS` already contains `--router`): should research and writing prompts that take several searches or reads — comparisons, summaries, texts that need no code — go to the `noctis:lite` subagent, so the main session keeps its context for the code? A short fact question that one search answers stays with the main session either way. The router stays off unless the user says yes: `--router on` for yes, `--router off` for no.

**Step 2 — say in one line what setup is about to change** — `permissions.defaultMode` → `auto` on the first setup of this account (Claude works without asking; never `bypassPermissions`; a later setup leaves the mode as it is unless `--permissions` is given), the default model → the profile's code model, its effort → saved for that model in `modelSettings` (xhigh and below; `env.CLAUDE_CODE_EFFORT_LEVEL` for max), the status line, `env.CLAUDE_CODE_ENABLE_FUNCTION_HOOKS` → `1` when it is missing (lean compaction; Claude Code's early-access switch, which loads the hooks module of every installed plugin), `autoCompactWindow` → `313000` when neither it nor `CLAUDE_CODE_AUTO_COMPACT_WINDOW` is set (Claude Code then compacts by about 280k tokens of context, in a 1M window too; beside a percent, `1000000`, so the percent holds for every model), and marketplace auto-update on — and mention `--permissions keep`, `--no-model`, `--no-lean`, `--compact-at off`, `--updates keep`. Then **run the setup** and show its output verbatim:

```bash
"${CLAUDE_PLUGIN_ROOT}/bin/noctis" setup --profile code <flags>
```

(PowerShell: prefix the command with `& `.) Replace `--profile code` with `--profile search`, `--profile balanced`, `--profile synex`, or for custom: `--code opus:high --research sonnet:high --planning opus --digest haiku --explore haiku --fallback sonnet:high`. `<flags>` is the `--router` answer from Step 1 and `$ARGUMENTS` written as flags, because setup refuses any word or option it does not know: a plain word becomes its flag (`search` → `--profile search`, a folder → `--config-dir <folder>`), and anything with no flag below is left out and mentioned to the user. The flags: `--preset conservative|balanced|aggressive` (pause thresholds), `--no-model` (leave `settings.json > model` alone), `--no-lean` (turn lean compaction off; a `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS` that setup wrote is taken back, one the user set stays), `--compact-at <tokens>|<percent>%|off` (where Claude Code compacts: a token count from 67000 to 967000, such as `280k` or `600k`, for which setup writes `autoCompactWindow` 33000 higher; a percent of each model's window from 10 to 100, such as `60%`, for which it writes `env.CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` with `autoCompactWindow` `1000000`, so the percent is taken of each model's whole window; `off` leaves it to Claude Code and takes back what setup wrote, one the user set stays), `--config-dir <dir>` (repeat for several accounts), `--permissions keep` (do not touch `permissions.defaultMode`, on this run or on later ones, and relaunch in the session's own mode: a `resume.permissionMode` of `auto` becomes `inherit`; without `--permissions` the first setup on an account sets it to `auto`, or `acceptEdits` where `auto` is unavailable, so unattended work never waits on a permission prompt, and a later run leaves it as it is — never `bypassPermissions`), `--permissions auto|acceptEdits|default|plan` (set that mode on this run), `--updates keep`, `--router on|off` (research routing). The output names the permission mode from before the first setup and how to go back to it, or says that it left the mode as it was. Exit code 2 means setup changed nothing and named what it did not understand: correct that and run it once more, or ask the user.

**Step 3** — tell the user to restart Claude Code (`/exit`, then `claude --continue`, which picks the conversation up): Claude Code reads where it compacts only as it starts, so `/reload-plugins` alone would leave this session compacting at its old point. The roles can be changed any time by running this skill again, and `noctis selftest` (the `bin/noctis` binary is on the Bash tool's PATH while the plugin is enabled) verifies scheduling, notifications and hook speed.
