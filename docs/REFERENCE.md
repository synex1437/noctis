# Noctis — reference

The README says what the plugin does and how to install it; this page lists every command, configuration key, host adapter and file.

## Commands

Two flags work with every command: `--account <dir>` is the account folder whose `noctis/` data is used (default `CLAUDE_CONFIG_DIR`, else `~/.claude`; when `--host` or `NOCTIS_HOST` names another tool, that tool's home), and `--host <id>` picks the host adapter (`claude`, `codex`, `antigravity`, `droid`, `copilot`). `setup` and `install` configure every account named with `--config-dir` or `--account` (both can be repeated, a leading `~` is expanded, duplicates are dropped). Flags are written `--flag value` or `--flag=value`; `-h` and `-?` print the help, as `--help` does, and `-v` prints the version, as `--version` does. An unknown `--host` or `NOCTIS_HOST` makes any command you run exit 2 with the list of valid ids, and a valid `--host` wins over a bad `NOCTIS_HOST`; the commands a host or noctis itself starts (`hook`, `statusline`, `resume`, `sleeper`, `ensure`, `release-check`, `webhook`, `selftest-mark`, `state-write`) ignore the bad value and use the configured host, Claude Code by default.

| `queue trust` \| `untrust` \| `status` | `--file <path>`, `--cwd <dir>`, `--sid <id>` | Trusts or distrusts a queue file, or says whether it is trusted (see `queue.requireTrust`); `status` lists the items and lines added or changed since the trust, or says that the trust came from a noctis that recorded none of them. `trust` and `status` also name each `(after …)` reference in an open item that is written as a tag, an issue or an item number and matches none, which holds nothing back: up to 50, each cut to 40 characters, then a count of the rest. A here-document read by `cat`, `tee`, `git` or `gh` that cannot run commands (its delimiter quoted, or no `$(` or backtick in it) is data and is left out, unless the rest of the line runs code another way (a `$(` given as an option's value, as in `-m "$(cat <<'EOF'`, does not count), so a commit or pull-request message written that way may name the command. Not recognized: a name or command built at run time (from a variable, `printf`, `base64` or pieces joined together), a script file that runs the command, and a program not named above that runs a command it is handed; the check stops Claude's direct call and is not a sandbox. Every other shell call gets no answer from noctis. By the same reasoning the PreToolUse hook denies a `Write`, `Edit` or `MultiEdit` of Claude's whose path resolves to noctis's own `state.json` (which holds the trust records) or `config.json` (which sets whether trust is required and any `queue.verifyCommand`), symbolic links and Windows junctions followed, and shows the user a notice; the user edits those files themselves or with `noctis setup`. Default file: the queue file in `--cwd` (the current folder), else that session's checklist. A relative `--file` is read from `--cwd`; `trust` and `status` refuse a path that is not a file, change nothing and exit 1, while `untrust` takes any path so a stale record can be removed |

That rule is for Anthropic's own API: when the account's Claude Code uses another provider or a gateway — one of the `CLAUDE_CODE_USE_BEDROCK`, `_VERTEX`, `_FOUNDRY`, `_ANTHROPIC_AWS`, `_ANTHROPIC_GOOGLE_CLOUD`, `_MANTLE` or `_GATEWAY` switches set to `1`, `true`, `yes` or `on`, or an `ANTHROPIC_BASE_URL` on a host outside anthropic.com, in the environment or in the `env` of its `settings.json` — the provider decides which ids exist, so any id made only of letters, digits and `. _ : @ / [ ] -` is taken, such as a deployment or gateway name, or an inference-profile ARN in the `roles` section of `config.json`; `noctis doctor` and the agent files follow the same rule. In a terminal without `--host`, it asks which tool |

Without `--title` and `--body` it sends a test message and ignores an open circuit |
| `version`, `help` | — | The version (`--version` and `-v` too); the commands in this table with one line each (`--help` and `-h` too). An unknown command exits 1 and lists them |

Called by the plugin itself: `hook`, `statusline`, `resume`, `sleeper`, `release-check`, `selftest-mark`. `state-write` is for the test harness: it replaces noctis's whole `state.json`, so it runs only when `NOCTIS_STATE_WRITE=1` is set (the harness sets it) and exits 1 otherwise, and the queue-trust check denies a Bash or PowerShell call of Claude's that runs it, since the state file holds the queue-trust records. `resume` without `--sid` prints its usage and exits 2.

A command you run that crashes prints `noctis <command> crashed: <reason>` with the path of `errors.log` on stderr and exits 1. The commands a host or noctis itself starts exit 0 after a crash, so a hook never fails the session; a crashed status line prints `∞ noctis error (errors.log)`. `webhook` is the exception: you run it yourself to test the webhook, so a crash in it exits 1 with that message too.

`noctis check` is the exit-code gate for crons, CI and other agents: `0` under every threshold, `10` inside the warn band, `11` a threshold is reached (the hooks would pause unattended work right now), `20` no or stale usage data (no reading, or one of the two windows last read longer ago than `usage.staleMinutes`, even while the other one is fresh), `2` an unknown `--host` or `NOCTIS_HOST`, `1` a crash of noctis itself (the reason is in `errors.log`). `11` also covers a window at the 100 % ceiling or about to cross it and a Fable session over the Fable threshold; a `budget.hardStop` pause is not reflected. It records nothing and never touches the network.

`report --json` is ccusage-compatible (`daily[]` with `inputTokens/outputTokens/cacheCreationTokens/cacheReadTokens/totalTokens/totalCost/modelsUsed/modelBreakdowns`) and adds `keptOffPrimary` — the tokens subagents spent on other models instead of the primary one, what those calls cost at API list prices (`cost`), what they would have cost on the primary model (`costOnPrimary`) and the difference (`savedVsPrimary`, below zero when those models cost more than the primary one). Its `basis` field says what these figures are: an API list-price estimate, not plan quota saved. The text and HTML reports print the difference with that label, and leave the line out when it is not above zero. Costs use the published list prices (informational on a subscription); `report.pricing` in `config.json` overrides or extends the table.

## Slash commands and agents

| Inside Claude Code | What it runs |
|---|---|
| `/noctis:setup` | Asks which roles profile you want (unless you pass `--profile` or a role flag) and whether research and writing prompts go to the `noctis:lite` subagent (unless you pass `--router`; the router stays off unless you say yes), then runs `noctis setup --profile …` with that answer as `--router on` or `--router off` and your words written as flags (`search` becomes `--profile search`, a folder `--config-dir <folder>`) |
| `/noctis:status` | `noctis status`, then `noctis why --last 10` |
| `/noctis:pause [minutes]` | `noctis off <minutes>`; the skill turns a duration such as `2 hours` into minutes (default 60, at most one week) |
| `/noctis:resume` | `noctis on` |

While one of these runs, Claude may use the plugin's own binary for that command without asking (for `/noctis:status`, `status` and `why`), and nothing else: any other command it runs meanwhile goes through your permission settings as usual. `/noctis:setup` and `/noctis:pause` start only when you type them; Claude cannot start them itself, even when a file it reads asks it to.

These four prompts pass the pause point, though not the 100 % ceiling (nor a window about to cross it), so you can check, pause or set up the plugin at a limit; a tool batch that only runs the plugin's own binary (plain Bash or PowerShell calls with plain arguments, no pipes, redirections or other commands) is not held either. `noctis why` shows them as `control-prompt`, `control-batch` and, at the ceiling, `block-control-prompt`. Your answer to a question the skill asks is an ordinary prompt: like any prompt you type it goes past the pause point, though not the ceiling.

**Prompts you type at a pause point.** A prompt you type is not parked at a pause point. It goes ahead with a warning, once per window and reset (`⚠ 5h window 93% (threshold 92%): your prompt goes ahead anyway. noctis stops it only at the usage limit.`; the second sentence is left out while `credits.allowPaid` is on), and Claude is told that the prompt runs past the pause point and to start no big new work beyond it; when a burst, a projection from stale data or an imminent compaction brings the pause forward, Claude is told that the usage is still under the pause point and why noctis pauses now. A wait already stored for the session is cancelled with its runner, since you are back at the keyboard. The turn the prompt starts runs to its end: its tool batches, its `Agent` and `Task` calls and its subagents are not held at the pause point; a new `Workflow` still meets its gate. What still parks the prompt, and stops its turn: the credit ceiling (100 %, or a window about to cross it), a pause for missing data (`blind`) and `budget.hardStop`. The turns that start by themselves after yours ends — a queue continuation, a relaunch, a wake — meet the pause point again, and so does a prompt noctis composed. `noctis why` shows `typed-prompt` for the prompt and `typed-turn` for the first batch or subagent call of its turn past the pause point; in `observe` mode they are `would-typed-prompt` and `would-typed-turn`, and nothing is shown. Antigravity has no prompt event, so there every turn meets the pause point.

Two agents come with the plugin. `noctis:lite` does research and writing on the `roles.research` model; it may write only `.adoc .csv .markdown .md .rst .srt .tsv .txt .vtt` files — the PreToolUse hook denies a `Write` to any other file, and to `CLAUDE.md`, `CLAUDE.local.md`, a file named like one of the `queue.files`, anything inside a `.claude` folder, anything inside the account folder (`CLAUDE_CONFIG_DIR` or `--account`, whatever its name; noctis keeps its queues and state there) and anything inside the plugin's own folder, because those files steer the main model — and its frontmatter keeps `Edit`, `MultiEdit` and `NotebookEdit` away from it. The hook follows the path the way the write does: through linked folders (Windows junctions among them) and through a link at its end, also one whose file does not exist yet, and a path with `..` is checked both where it leads past a linked folder and as it reads with the `..` folded. Each check applies to the path as given, to every link at its end and to the file the write lands in; a link the hook cannot follow (a loop, or more than 8 links in a row) is denied. The account and plugin folders are known by the folder itself, so a path that leads into one of them under another name, the folder a `~/.claude` link leads to among them, is denied too. Not covered: a file or folder that `CLAUDE.md`, a queue file or a project's `.claude` is a link to, written under its own name (an `AGENTS.md` that `CLAUDE.md` links to, say), and the files a `CLAUDE.md` pulls in with `@`. `noctis:digest` runs noisy commands (test suites, builds, long logs) on the `roles.digest` model and returns a digest; it never writes files (its frontmatter disallows the file tools, and the hook denies a `Write`). These write limits apply in observe mode too and are not journaled. A hand-made agent named in `router.agent` or `router.digestAgent` has to keep `Edit`, `MultiEdit` and `NotebookEdit` out of its tools the same way, because the hook does not apply this write policy to those calls (it sees `Edit` and `MultiEdit` only for the own-file check below, and never sees `NotebookEdit`); `noctis doctor` and the startup self-check name an agent file that allows one. Unless the router is off, the guard is paused or observe mode is on, a prompt that starts with `lite:` is always sent to `noctis:lite`; one that starts with `main:` or `fable:` never is. A session started with `claude --agent <name>` (or the `agent` setting) is guarded like any other main session; one that runs as the lite agent itself is not told to hand its research to that agent.

**Subagents at a limit (Claude Code).** Subagents and workflow agents meet the pause point and the credit ceiling on their own loop; in the turn of a prompt you typed, only the ceiling (see above). Past the pause point, a subagent's `WebSearch`, `WebFetch`, `Agent`, `Task`, `Workflow` or `Write` call is denied with an instruction to start no new work and report what it has; its first tool batch past that point carries the same instruction, and the next one ends the agent. At the ceiling it is ended at once. Batches that only deliver the report (`SubagentHandback`, `StructuredOutput`) pass, and a subagent's `Workflow` also meets the warn band and the fan-out headroom. Each agent cut short is named — `<type> agent <id> — stopped by the usage limit at <time>; its result is partial`, or `told at <time> to wrap up …; its result may be partial` — in the checkpoint, in the note a relaunch or wake starts with, and in the context after an in-hook wait, so the resumed session redoes that part instead of trusting a saved result. The journal actions are `deny-subagent-tool`, `warn-subagent` and `stop-subagent`. On the other tools, subagents are not guarded this way.

Claude Code hook events wired in `hooks/hooks.json`: `SessionStart` (on `startup` it also runs `noctis ensure`), `SessionEnd`, `UserPromptSubmit`, `PreToolUse` (`WebSearch|WebFetch|Agent|Task|Workflow|Write`, and `Bash|PowerShell|Edit|MultiEdit` for the `queue trust` check below and the check that Claude does not write noctis's own `state.json` or `config.json`), `PostToolBatch`, `StopFailure` (`rate_limit|overloaded|server_error|model_not_found|billing_error|account_on_hold|authentication_failed`), `Notification` (`quota_auto_resume_fired|quota_auto_resume_stale|quota_auto_resume_disabled`), `PostModelSwitch`, `TaskCreated`, `TaskCompleted`, `PostToolUse` (`Agent|Task`), `Stop`, `PermissionRequest` (`Read|Edit|MultiEdit|Write`; see `queue.auto`). In a run Claude Code treats as non-interactive (`CLAUDE_CODE_ENTRYPOINT` `sdk-cli`, which is `claude -p`, `sdk-ts`, `sdk-py` or `claude-code-github-action`), Claude Code starts the asynchronous `StopFailure` hook while it is already shutting down and does not always wait for it, so there the hook ignores SIGTERM, writes the payload to `<account>/noctis/pending/` and exits after starting a detached `noctis hook --input <file> --account <account>`; that copy stores the checkpoint, the retry and its scheduled relaunch, removes the file and never wakes the session in place. Interactive sessions keep the in-hook path and the same-session wake, and when the copy cannot be started the hook does the work itself. A `SessionEnd` that runs while such a hand-off (younger than an hour) is pending keeps the session's workflow record for the relaunch. On `startup` and `/clear`, `SessionStart` hands the new session the latest unused checkpoint of its folder (at most 7 days old), except one whose own session will still be resumed — its wait is pending or its relaunch is running. A checkpoint counts as used once its own session goes on: a prompt there passes the guard, or the guard is paused. Under `modules` it also names the hooks module `hooks/lean.js`, which Claude Code loads only with function hooks on (`CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1`); it hooks `session.start`, `session.compact` and `turn.complete`. A value of the wrong type or out of range in the `compaction` keys it reads is replaced by the shipped one. While `compaction.lean` is on and prompt caching is off (`DISABLE_PROMPT_CACHING`, the only time it trims), it declines a summary Claude Code computes ahead of time (`precompute`): once the rows are trimmed, Claude Code would discard that summary. A message it trims goes to the summary without Claude Code's handle, so Claude Code rebuilds it from its role, text and tool blocks alone (Claude Code's contract for a rewritten message); a message it leaves alone keeps its handle and stays whole.

**Parallel pauses.** Hooks of one session that pause for the same limit at the same moment — several Agent calls fanned out at once, or the per-call `PostToolUse` hooks of Codex and Droid — share one wait: a pause joins the stored wait when it is for the same window, its reset is within 2 s, it was stored less than 120 s ago and the pause is not a prompt. Every hook then holds until the reset, or until an early reset or fresh data releases the wait. A hook clears only the wait it stored itself; if another pause for the same reset replaced it, it holds on that one, and if a different pause replaced it (another window, or a wait handed to the runner), it stops with that pause's `work saved, auto-resume at …` message, followed by that pause's reason when it did not come from its pause point. `noctis why` logs these as `join-wait` and `wait-replaced`.

## Other AI coding tools

The engine is host-independent; a thin adapter per tool writes that tool's hook file, translates hook JSON in and out, reads usage where the tool exposes it, and resumes sessions with the tool's own command. `scripts/install.sh` / `install.ps1` (or `noctis setup` in a terminal) ask **which tool** with a numbered list; `--host <id>` skips the question. The answer can be the number, the id, the tool's full name, or three or more letters that start a word of exactly one tool's name (`ant`, `cop`); an empty answer means Claude Code, and anything else is asked again. On Windows the question appears in a console (PowerShell, cmd, Windows Terminal) but not in Git Bash or mintty, whose stdin is a pipe: pass `-Tool` / `--host` there. `install.ps1 -Tool` takes an id; a display name such as `'Codex CLI'` exits 2 with the list of ids.

| Tool | Hooks (file) | Usage windows read from | Pause before the wall | Queue mode, checkpoints | Resume after a wait | Notes |
|---|---|---|---|---|---|---|
| **Claude Code** (`claude`) | plugin `hooks/hooks.json` (exec form) | status line + OAuth usage endpoint | ✅ 5-hour, weekly; the scoped bucket switches the model | ✅ | `claude --resume <id>` | Reference host; model fallback, routing and same-session wake are Claude-only |
| **OpenAI Codex CLI** (`codex`) | `~/.codex/hooks.json` (`SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `Stop`, `SessionEnd`) | `codex app-server` → `account/rateLimits/read` (windows classified by duration, so the on-and-off 5-hour window is handled) | ✅ | ✅ | `codex exec resume <id> --skip-git-repo-check -- "<prompt>"` | Run `/hooks` once in Codex and trust the plugin's hooks; Codex has no custom status line; no error hook: a 429 the guard did not see coming is not retried |
| **Antigravity CLI** (`agy`, Google) | `~/.gemini/config/hooks.json` (`PreToolUse`, `PreInvocation`, `PostInvocation`, `Stop`) + `statusLine` in `~/.gemini/antigravity-cli/settings.json` | the status-line payload's `quota` (remaining fraction + reset time per bucket) | ✅ | ✅ (`Stop` → `decision: continue`) | `agy --conversation <id> --output-format text -p "<prompt>"` | `PostInvocation` terminates the loop at the threshold; an `error` stop is handled like a failed turn in Claude Code: a quota message as a limit, an overload with the backoff, sign-in and billing errors not retried, anything else retried on the `wait.retryMinutes` steps |
| **Factory Droid** (`droid`) | `~/.factory/hooks.json` | — (`/limits` is interactive only) | — | queue only | `droid exec --session-id <id> --auto high --output-format text "<prompt>"` | Limit guard off; queue mode works; Droid has no error hook, so nothing is retried and no checkpoint is written |
| **GitHub Copilot CLI** (`copilot`) | `~/.copilot/hooks/noctis.json` (exec form) | — (monthly credits, no windows) | — | ✅ (`agentStop`; the 8-block cap is respected via `stop_hook_active`) | `copilot --resume=<id> -p "<prompt>"` (`--allow-all-tools` only with `resume.copilotAllowAllTools: true`) | Copilot's camelCase payloads carry no `hook_event_name`, so the engine tells the event from the payload's shape; there an `errorOccurred` counts only when Copilot marks it `recoverable: false`, and an error Copilot recovers from itself is left alone. Claude Code's relaunch runs in the folder the session started in (its `CLAUDE_PROJECT_DIR` at the pause), not in a subfolder Claude had moved into with `cd`: Claude Code gives a resumed session's hooks the folder it is started in as `CLAUDE_PROJECT_DIR`, so this keeps the session's queue in reach. A session started with `claude -w` has its worktree as that folder, and one that entered a worktree with `EnterWorktree` is put back into it by Claude Code. The queue the relaunch prompt names is looked up as the hooks look it up, in the folder the session started in and then in the one it paused in; when it is found only in the one it paused in (a subfolder's own queue), the relaunch runs there instead, where its hooks find it again. The relaunch also passes `--model`, `--effort` and `--permission-mode` (and `--remote-control` with `resume.remoteControl`); `resume.extraArgs` are added only when they are flags that cannot widen what the relaunched session may do, the ones that narrow it included: for Claude Code `--verbose`, `--ax-screen-reader`, `--debug`/`-d` (with or without a filter), `--remote-control` (with or without a name), `--name`/`-n`, `--disallowedTools`/`--disallowed-tools`, `--tools`, `--max-budget-usd`, `--max-turns` and `--strict-mcp-config`; for Codex `--model`/`-m`, `--color`, `-c`/`--config` setting `model` or `model_reasoning_effort`, and `-s`/`--sandbox` with `read-only`; for Copilot `--model`, `--log-level`, `--no-color`, `--screen-reader` and `--deny-tool`; for Droid `--model`/`-m` and `--reasoning-effort`/`-r`; for Antigravity `--verbose`. A flag's value is the next item or follows `=`; `--disallowedTools`, `--disallowed-tools` and `--tools` without `=` take every item up to the next flag. Everything else, such as `--settings`, `--allowedTools`, `--add-dir`, `--mcp-config`, another `--sandbox` value, Codex's `--dangerously-bypass-hook-trust` (see [docs/HOSTS.md](HOSTS.md)), the permission flags (`resume.permissionMode`, `resume.copilotAllowAllTools` and `resume.droidAuto` decide those) or a stray value, is dropped, named in one warning per relaunch and journaled as `extra-arg-dropped`. Claude Code and Codex get the prompt after `--`, so a prompt is never read as an option, and for every tool a prompt that would start with `-` starts with `Continue. ` instead. Every relaunch starts the tool without the session markers Claude Code gives its hooks (`CLAUDECODE`, `CLAUDE_CODE_SESSION_ID`, `CLAUDE_CODE_CHILD_SESSION`, `CLAUDE_CODE_SESSION_ATTENDED`, `CLAUDE_PID`, `AI_AGENT`, `CLAUDE_EFFORT`, `TRACEPARENT`, `CLAUDE_CODE_ENTRYPOINT`), so the relaunched session carries no marker of the session that paused and starts as a session of its own.

Not supported (checked September 2026): Gemini CLI (consumer access ended June 2026 — use Antigravity CLI), Kiro CLI (`AgentStop` cannot block), Cursor / OpenCode / Amp / Qwen Code (hooks exist but no script-readable limits; queue-only support is on the list), Roo Code (archived), Cline / Goose / Crush (no continue hook).

Install for another tool from the zip or clone: `./scripts/install.sh --host codex` (macOS/Linux) or `.\scripts\install.ps1 -Tool codex` (Windows); the plugin lands in `<tool home>/noctis/plugin/` with its config next to it, and `noctis doctor --host codex` checks the wiring. Uninstall: the same command with `--uninstall` / `-Uninstall` — it removes only the plugin's own hook entries (on Antigravity also the `statusLine` it wrote) and the `<tool home>/noctis/plugin/` copy, and cancels the relaunches still pending; the config and logs next to it stay unless you add `--purge` / `-Purge`.

**Honest status:** the four adapters implement each tool's documented hook, usage and resume contracts and pass the black-box lab against stand-ins of those tools. A weekly CI job (`real-tools.yml`) installs the real Claude Code, Codex and Copilot CLIs and checks that the main flags the plugin passes are still there, and that `codex app-server` answers the handshake; it never signs in or runs a model, and Antigravity and Droid are not checked. No adapter has run a real session end to end yet — smoke tests are in [docs/HOSTS.md](HOSTS.md); reports with the tool's version are welcome.

## Limits

Usage data comes from Claude Code's official `statusLine` payload (`rate_limits`, Claude Code ≥ 2.1.251) and from the undocumented OAuth usage endpoint, which supplies the scoped bucket and backs up the 5-hour and weekly windows when status-line data is stale — keep an eye on `errors.log` after Claude Code updates; `selftest` reports the tested version range. Same-session wake relies on `asyncRewake`, which is documented as observational; the scheduled relaunch covers the case where it stops working. Lean compaction runs on Claude Code's early-access function hooks (tested with 2.1.281), which may change between releases; without them, compaction is Claude Code's alone.
